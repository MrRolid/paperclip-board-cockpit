# Prompt-injection regression corpus

This corpus measures a deliberately narrow, auditable regex layer. It is defense in depth, not the primary security boundary. Board Cockpit remains read-only, wraps project content as untrusted data, attaches plugin-generated provenance and lints generated advice independently.

## Adding samples

- `injection/<lang>.txt`: one injection-like positive sample per line. A committed positive must be detected by the current rules.
- `benign/<lang>.txt`: one realistic Paperclip task, comment or handoff line per line. Any match is a regression.
- `advice-unsafe/<lang>.txt`: one unsafe generated-advice line per line.
- `advice-benign/<lang>.txt`: one safe/negated advice line per line. Any warning is a regression.
- Keep examples synthetic. Never commit real credentials, private issue text, hostnames or customer data.
- Do not weaken a benign case merely to raise recall. Precision wins because input matches are redacted before the advisor sees them.
- Phrasings that cannot be detected without a benign collision stay out of the public positive corpus and are tracked privately by the operator.

Matching is performed after NFKC/NFD normalization, Latin diacritic folding, selected Latin homoglyph folding and whitespace collapse. Patterns from every language are applied to every snapshot regardless of the selected UI locale.

The corpus is intentionally not a recipe for bypasses: it contains only phrasings already caught by the detector. Missed adversarial variants belong in private testing until a precise rule can cover them without increasing the benign false-positive set.
